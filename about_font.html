字体布局和渲染

Aug 15, 2025

从我的成长经历出发，前端入门虽第一课就接触到了字体本身，但因浏览器对文字的封装，往往对字体的了解浮于表面，而忽略了字体的复杂性。很长一段时间,我都将字体渲染当做非常简单的事情：“不就是一行 HTML 代码就能解决嘛”。然而花点心思，发现字体并不简单。

字体的历史

先简单回顾字体的发展史：

时间 产物 详情 涉及技术 截图
20世纪 60 ~ 80 年代 点阵字体 / Bitmap Font 早期显示器和打印机分辨率极低，只能用“点阵”方式表示文字。

优点：实现简单
简单：放大缩小，锯齿验证		 ![[bitmap_font.png]]
20世纪 80 年代 ~ 至今 矢量字体和轮廓字体 Type 1（1980）：Adobe首次利用贝塞尔曲线描述字体，实现矢量字体。2023 年 1 月 已停止支持。
 ![[bizier.png]]
TrueType 字体（1991），苹果和微软联合研发。采用二次贝塞尔曲线 + Hiniting。 抗锯齿（Anti-aliasing）技术：让字体边缘更平滑

Hinting 技术：通过内嵌 Hinting 指令，知道渲染引擎如何对齐笔画，优化像素分布
OpenType（1996），微软和Adobe联合研发，支持更多的排版特性，如连字、变体等。成为现代操作系统和网页的主流字体。
千禧年，2000年至今 更多的格式或表达 WOFF / WOFF2 字体，体积小，加载快。
可变字体 / Variable Font（2016）：OpenType 1.8 引入可变字体，支持字体内多种粗细、宽度、斜体，提供灵活性和性能。 轮廓插值（Glyph Outline Interpolation）：可变字体的每个字形（glyph）不是单一轮廓，而是多个“主控点”轮廓（master outlines）的集合
SDF / Signed Distance Field：距离场表达，合理利用 GPU 并发特性，能实现更高效、特效的字体渲染。

从编码到字体

因为字体过于复杂，一般存储数据，并不会将字体储存在文件中。而是仅记录对应的数据。这也是为什么用采用不同的编码解析会出现乱码的情况。

![[unicode.png]]
![[encode.png]]

一般，编码和字体的关联方式：

概念 主要作用 触发条件 配置方式 应用
Font Link 多字体组合/联用 字体文件缺字 注册表/字体配置 Windows XP/7/10/11 都有 Font Linking 和 Font Substitute 机制
Font Fallback 优先级回退 字体缺字或未指定 应用/浏览器/系统 CSS 的 font-family 列表
操作系统和字体库（如 FreeType、Skia、CoreText）都实现了智能字体回退，自动查找支持当前字符的字体。
Font Substitute 字体不可用时替换 字体未安装/损坏 系统级配置 Android 的“系统字体池”，macOS 的“字体集合”

当然，编码和字形（Glyph）不完全是一一对应的。

  • 比如： é 可以是 U+00E9 也可以是 U+0065（e）+ U+0301（重音符）。
  • 比如： Emoji，Emoji 可能是由多个 Unicode 表示的，如：一个家庭是由成员 + 零宽连字符（ZWJ）组合而成（👨（U+1F468）+ ZWJ（U+200D）+ 👩（U+1F469）+ ZWJ（U+200D）+ 👧（U+1F467）+ ZWJ（U+200D）+ 👦（U+1F466） = 👨‍👩‍👧‍👦） 。且由于各种历史原因，不同的平台有不同的实现，导致处理 Emoji 除了状态机外，还需要各种 hack 的手段。参考资料：了解前端emoji

字体渲染

一般会经历三个阶段：Shaping（塑形） → Layout（排版） → Render（渲染）

塑形

字体不是简单的排列，不同字体组合在一起，对于字体本身也是有变化的。最直接的例子就是 RTL 中的阿拉伯语言，单个字符和连起来，看起来就是完全两个样子。比如：ب س ب ب == ! بسبب

渲染：光栅化和抗锯齿 / Raster & Anti-aliasing

一种简单的抗锯齿方式，字体不是非黑即白，将字体放大数倍来绘制，缩小到原来大小，未满一个用灰阶补点。即 超采样抗锯齿（Supersampling/Multisampling）。

![[anti_aliasing.png]]

然后还有额外的抗锯齿方式：

  • 灰度抗锯齿（Grayscale Anti-aliasing）：在字体边缘处，根据覆盖像素的面积，计算灰度值（0~255），让边缘像素呈现半透明，视觉上更平滑。
  • 子像素抗锯齿（Subpixel Rendering/ClearType）：从灰度值到RGB混合，计算更具体的色值。具有比灰度更清晰的表达能力，主流的算法，Windows ClearType、Macos 的 Quartz，Web 采用这种方式。

-![[subpixel.png]]

  • SDF 抗锯齿（Signed Distance Field）：根据距离来表示灰度。

技术实现

最开始的字体的渲染并不具备跨平台性，每个平台都有其具体的实现。比如 Linux 上的 FreeType，Windows 上的 Direct Write，Mac 的 Core Text + Quartz 2D。Skia 作为跨端的渲染引擎，将抽象各平台实现的共性，以子集的方式表达。

字体格式

这里 FreeType 针对 字形的约定给了一些抽象：Link，如字形指标、字距调整、如果光栅化等。

以前端最为熟悉的 WOFF 为例，各名词之间的关系：

  • WOFF2 是 WOFF 文件应用 Brotli 压缩算法后的产物，拥有更小的体积，但本质还是 WOFF 格式。
  • WOFF 字体数据集，则是基于表格的 sfnt 结构的重新打包，使其在 Web 传播时更加高效安全，所以 WOFF 是基于 sfnt 结构的。
  • sfnt 结构，是可缩放字体的容器格式，是一种文件结构标标准。sfnt 规定字体由多个表组成，每个表存储不同的字体信息。TrueType、OpenType 都是基于 sfnt 标准的。
  • TrueType、OpenType 都是基于贝塞尔曲线描述字体的文件格式。不同的文件格式，在渲染字体上有不同的高级特性，比如 TrueType支持 Hinting 等。

OpenType 属性

四舍五入，Woff2 就是 OpenType，所以看一下 OpenType 具体有哪些内容。

OpenType 是微软和 Adobe 在1996年推出的字体，用于描述字体的形状、颜色、布局信息等。从微软的文档可知道，OpenType 可以使用 TrueType 或 CFF 轮廓，都有的公共属性，然后分别存储 TrueType 或 CFF 轮廓的信息。

可以简单理解，字体的资源就是一个个key map，只不过这些数据非常底层，存储贴近硬件，索引和指针必不可少，格式紧凑，甚至涉及字节的对齐，从而尽可能利用每一个比特。

字体文件一般由文件头、表目录、字体数据表、其它扩展信息组成。文件头包含一个识别签名，并说明字体的具体类型。紧跟着的表目录，是索引表，交代每个字体数据的大小和位置。然后是字体的一些数据，交代本身的一些布局属性，以及绘制方式：

描述字体形状，可以是一些贝塞尔控制点，或多个自行组合，如：

SDF

绝大多数的矢量绘制，都是CPU 级别的绘制。不同于 Canvas 2D 的路径绘制，有时候为了能利用 GPU 的加速，会提出一些并行的算法。在绘制文字测，会用到 SDF 的算法。

类型 典型应用 优势 劣势
位图 点阵字体、图标、像素艺术、图片 实现简单，存储直接 放大易失真，灵活性低
SDF 字体渲染、游戏UI、实时特效 可缩放、边缘平滑、特效强 生成复杂，体积较大

一般来说，无论2d或者3d资产都有隐式（implicit）和显式（explicit）两种存储方式，比如3d模型就可以用mesh直接存储模型数据，也可以用sdf、点云(point cloud)、神经网络(nerual rendering)来表示，2d资产（这里指贴图）也是如此。比如贴图一般直接使用rgb、hsv等参数来进行表示，但这样子再放大图片后会出现锯齿，所以想要获取高清的图像就需要较大的存储空间，这时候就需要矢量表示，在2d贴图中sdf就是为了这种需求产生的。

SDF 是隐式的表示，SDF 可用于表示 3d 资产，自然而然也可以表示 2d 资产。
SDF 的核心是：对于每一个像素，计算它到最近的轮廓边界的距离（带符号，内外区分）。

  • SDF 距离值 < 0：说明该像素在图形内部；
  • SDF 距离值 = 0：在边界上；
  • SDF 距离值 > 0：在图形外部。

主要难点在于如何表示 SDF，即生成。

假设输入图像尺寸为 N × N，轮廓点总数为 M。

算法 概要说明 复杂度 论文
朴素算法 对每个像素，遍历所有轮廓点，计算距离，取最小值。 O(N² × M)
Jump Flooding Algorithm (JFA) O(N² × log N) Link
距离变换（Distance Transform）：如 Danielsson’s algorithm、Felzenszwalb’s algorithm O(N²) Link
查询复杂度：O(1)

SDF 纹理可以用 RGBA 格式，其中 R 通道为距离，GBA 通道为颜色。

虽然 SDF 绘制速度很快，但是 SDF 毕竟是基于像素的运算，所以同比矢量字体，超大分辨率时，会模糊，而且单个 SDF 文件会很大，虽然支持描边、阴影，发光，但不支持变形变体、Hinting，所一般主流的字体文件还是基于矢量轮廓。
